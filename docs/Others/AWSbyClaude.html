1. Introduction to AWS

Amazon Web Services (AWS) is the world's leading cloud platform (launched 2006), offering 200+ services across compute, storage, databases, networking, AI/ML, security, and more. It operates in Regions worldwide, each made up of multiple Availability Zones (isolated data centers) for high availability.

2. IAM — Identity & Access Management

IAM controls authentication (who you are) and authorisation (what you can do) in AWS. Every API call to AWS is signed and evaluated against IAM policies. Getting IAM right is the foundation of AWS security.

IAM Roles for Services

A Role is the recommended way to grant AWS services permissions. No long-lived credentials are stored. EC2, Lambda, ECS tasks, and other services assume a role and receive short-lived temporary credentials via the instance metadata service.

# Attach role to an EC2 instance at launch (instance profile)

aws ec2 run-instances --iam-instance-profile Name=MyAppRole ...

# Inside the EC2 instance, the SDK auto-fetches credentials:

# http://169.254.169.254/latest/meta-data/iam/security-credentials/MyAppRole

# No AWS_ACCESS_KEY_ID needed — zero stored credentials

3. S3 — Simple Storage Service

S3 is AWS's object storage service. Objects (files) are stored in buckets. S3 is infinitely scalable, globally durable (11 nines = 99.999999999%), and the backbone of most AWS architectures — used for static files, backups, data lakes, and as the source/destination for many AWS services.

Full path of the object: "images/2024/photo.jpg"; "/" is a logical separator, not a real folder

Versioning

Keeps all versions of an object; protects against accidental deletion and overwrites

Presigned URL

Temporary URL granting time-limited access to a private object without exposing credentials

Key Features

S3 Versioning: once enabled on a bucket, every overwrite/delete creates a new version; old versions are retained and can be restored. A delete marker is added rather than actually deleting.

S3 Lifecycle Rules: automatically transition objects between storage classes or expire them after a number of days. Example: move to IA after 30 days, Glacier after 90 days, delete after 365 days.

Server-Side Encryption (SSE): S3-Managed Keys (SSE-S3), KMS-Managed Keys (SSE-KMS), or Customer-Provided Keys (SSE-C). SSE-S3 is enabled by default on all new buckets.

AWS CLI — S3 Examples

# Create bucket (bucket names are globally unique)

aws s3 mb s3://my-unique-bucket --region eu-west-1

# Upload a file

aws s3 cp ./photo.jpg s3://my-bucket/images/photo.jpg

# Sync local folder to S3 (only changed files)

aws s3 sync ./dist/ s3://my-bucket/static/ --delete

# Generate presigned URL valid for 1 hour

aws s3 presign s3://my-bucket/private.pdf --expires-in 3600

# List objects with size

aws s3 ls s3://my-bucket/images/ --recursive --human-readable

4. VPC — Virtual Private Cloud

A VPC is your own isolated, private network in AWS. You define the IP range, create subnets, control routing, and set firewall rules. Every AWS account gets a default VPC per Region; production workloads should always use a custom VPC.

Auto Scaling Groups (ASG)

An ASG automatically adjusts the number of EC2 instances based on demand. It replaces unhealthy instances, distributes across AZs, and integrates with ELB to register/deregister instances automatically.

ASG configuration:

Min: 2 ← always at least 2 instances running

Desired: 3 ← current target

Max: 10 ← never exceed 10

Scaling policy (Target Tracking):

Keep average CPU at 60%

CPU > 60% for 3 minutes → scale OUT (add instances)

CPU < 60% for 15 minutes → scale IN (remove instances)

Health check: ASG terminates unhealthy EC2, launches replacement.

AZ balance: ASG keeps instances spread evenly across AZs.

6. RDS & DynamoDB

RDS — Relational Database Service

RDS is a managed relational database service. AWS handles provisioning, patching, backups, and replication. You manage schema, queries, and access. Supported engines: MySQL, PostgreSQL, MariaDB, Oracle, SQL Server, and Aurora.

Feature

Description

Multi-AZ

Synchronous standby replica in another AZ; automatic failover in 1-2 min on primary failure

Read Replicas

Asynchronous copies in same or different Regions; scale read traffic; can be promoted

Automated Backups

Daily snapshot + transaction logs; restore to any point in time within retention window

RDS Proxy

Connection pooler between app and DB; reduces connection overhead for Lambda/ECS

Aurora

AWS-native MySQL/PostgreSQL compatible engine; 5× faster than MySQL, auto-scales storage

Aurora Serverless

Aurora that scales capacity automatically to zero when idle; pay per ACU-second

DynamoDB

DynamoDB is a fully managed, serverless NoSQL key-value and document database. It delivers single-digit millisecond performance at any scale. There are no servers to manage, no schema to define upfront, and capacity scales automatically with DynamoDB On-Demand mode.

Concept

Description

Table

Top-level container for items (rows)

Item

A single record in a table; equivalent to a row (can have variable attributes)

Attribute

A named data element within an item; equivalent to a column

Partition Key (PK)

Primary hash key; determines which partition an item lives on; must be unique (simple PK)

Sort Key (SK)

Optional second dimension of the primary key; PK + SK must be unique together (composite PK)

GSI

Global Secondary Index — alternate query pattern on non-key attributes; eventually consistent

LSI

Local Secondary Index — alternate sort key for same partition key; strongly consistent

On-Demand mode

Pay per request; scales to any traffic instantly; no capacity planning

Provisioned mode

Set Read/Write Capacity Units (RCU/WCU); cheaper if traffic is predictable

DynamoDB Streams

Change data capture; triggers Lambda on item create/update/delete

9. SQS, SNS & CloudWatch

SQS — Simple Queue Service

SQS is a fully managed message queue. Producers send messages to a queue; consumers poll and process them. Messages are retained for up to 14 days. SQS decouples producers from consumers so they can scale independently.

Aspect

Standard Queue

FIFO Queue

Ordering

Best-effort (messages may arrive out-of-order)

Guaranteed FIFO, exactly-once processing

Throughput

Unlimited

300 TPS (3,000 with batching)

Deduplication

May deliver duplicates (at-least-once)

Deduplication window prevents duplicates

Use case

High-throughput, order-insensitive tasks

Financial transactions, order processing

Suffix

No special suffix

Queue name must end with .fifo

Key SQS properties: Visibility Timeout — after a consumer receives a message, it becomes invisible to others for this duration (default 30s); if not deleted, it reappears. Dead-Letter Queue (DLQ) — messages that fail processing N times are moved to a DLQ for inspection.

SNS — Simple Notification Service

SNS is a fully managed pub/sub messaging service. Publishers send to a Topic; SNS fans out to all Subscribers simultaneously (SQS queues, Lambda, HTTP endpoints, email, SMS). Delivery is push-based — no polling needed.

Common Interview Questions

Question

Key answer points

What is an IAM Role and why use it instead of access keys?

A Role issues short-lived temporary credentials via STS; no static secret to store, leak, or rotate. Services (EC2, Lambda) assume roles automatically.

What is the difference between a Security Group and a NACL?

SG = stateful, instance-level, Allow-only rules. NACL = stateless, subnet-level, Allow + Deny rules. SG is the primary tool; NACL adds an extra subnet-level layer.

How does S3 achieve 11 nines of durability?

Objects are redundantly stored across multiple AZs (minimum 3) within a Region; checksums verify integrity on every read and write.

What is RDS Multi-AZ?

Synchronous standby replica in a different AZ. On primary failure, AWS updates the DNS endpoint to the standby in ~1-2 minutes. Standby is not readable — it is only for HA.

What is a Lambda cold start and how do you mitigate it?

First invocation requires container init + runtime load (~200ms-1s). Mitigations: Provisioned Concurrency (pre-warms containers), smaller packages, Graviton2 runtime.

When would you use SQS vs SNS?

SQS = one consumer, pull-based, retry/DLQ built in, decoupling. SNS = fan-out to multiple subscribers simultaneously (push). Fan-out pattern: SNS → multiple SQS queues.

What is the difference between ECS and EKS?

ECS is AWS-native, simpler, less operational overhead. EKS is managed Kubernetes — portable, larger ecosystem, but needs K8s expertise. Choose ECS unless you need K8s portability or already use Kubernetes.

How do you pass secrets to an ECS task / Lambda?

Store in AWS Secrets Manager or SSM Parameter Store. Grant the task/function IAM role permission to read the secret. The SDK fetches it at runtime — never bake secrets into images or env vars in code.
