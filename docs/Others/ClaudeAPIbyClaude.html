1. What Is Tool Use?

Tool Use (also called Function Calling) lets you give Claude a set of tools — custom functions — it can choose to invoke when answering a question. Claude decides when a tool is needed, generates the arguments, and then YOUR code actually executes the function and returns the result. Claude synthesizes the result into a final answer.

This is the core pattern for building AI agents that interact with the real world: querying databases, calling APIs, reading files, controlling systems.

3. Defining Tools

Each tool is a dictionary with three required fields: name, description, and input_schema. The input_schema follows the JSON Schema standard.

Tool Schema Structure

tool = {

"name": "get_weather", # unique identifier

"description": "Get current weather in a city. "

"Returns temperature and conditions.",

"input_schema": {

"type": "object",

"properties": {

"location": {

"type": "string",

"description": "City and state, e.g. Prague, CZ"

},

"unit": {

"type": "string",

"enum": ["celsius", "fahrenheit"],

"description": "Temperature unit"

}

},

"required": ["location"] # unit is optional

}

}

Field Rules

Field

Rule

name

Letters, numbers, hyphens, underscores only. Max 64 chars. Regex: ^[a-zA-Z0-9_-]{1,64}$

description

Write 2-4 sentences. Explain WHAT it does, WHEN to call it, and any caveats. Quality here matters.

input_schema

JSON Schema — must have type: "object". List only truly required fields in "required".

enum

Use when a parameter must be one of a fixed set of values.

Note: Claude reads the description to decide whether and how to call the tool. A vague description leads to wrong or missed tool calls.

JSON Schema — Common Property Types

Type

Example

"string"

"location": {"type": "string"}

"integer"

"count": {"type": "integer"}

"number"

"price": {"type": "number"}

"boolean"

"include_tax": {"type": "boolean"}

"array"

"tags": {"type": "array", "items": {"type": "string"}}

"object"

"address": {"type": "object", "properties": {...}}

enum (fixed choices)

"unit": {"type": "string", "enum": ["kg", "lb"]}

4. Basic Tool Use — Single Tool

A tool use conversation has two turns: the first returns a tool_use block, the second (after you execute the tool) returns the final answer.

Step 1 — Send Request with Tools

import anthropic

client = anthropic.Anthropic()

response = client.messages.create(

model="claude-opus-4-7",

max_tokens=1024,

tools=[{

"name": "get_weather",

"description": "Get current weather for a city.",

"input_schema": {

"type": "object",

"properties": {

"location": {"type": "string"}

},

"required": ["location"]

}

}],

messages=[{"role": "user", "content": "Weather in Prague?"}]

)

Step 2 — Detect Tool Call in Response

# Claude returns stop_reason="tool_use" when it wants to call a tool

print(response.stop_reason) # "tool_use"

print(response.content) # list of content blocks

# content blocks may include text + tool_use blocks

for block in response.content:

if block.type == "tool_use":

print(block.name) # "get_weather"

print(block.id) # "toolu_01Abc..." -- unique call ID

print(block.input) # {"location": "Prague, CZ"}

Response Content Structure

# Example response.content:

[

TextBlock(type="text", text="I'll check the weather..."),

ToolUseBlock(

type="tool_use",

id="toolu_01Abc123",

name="get_weather",

input={"location": "Prague, CZ"}

)

]

Step 3 — Execute Tool & Send Result Back

# 1. Execute your real function

tool_result = get_weather("Prague, CZ")

# e.g. "12°C, partly cloudy"

# 2. Append assistant message (with the tool_use block)

messages = [

{"role": "user", "content": "Weather in Prague?"},

{"role": "assistant", "content": response.content}, # full content list

]

# 3. Append tool result as a new user message

messages.append({

"role": "user",

"content": [{

"type": "tool_result",

"tool_use_id": "toolu_01Abc123", # must match block.id

"content": "12°C, partly cloudy"

}]

})

# 4. Send back — Claude gives the final text answer

final = client.messages.create(

model="claude-opus-4-7", max_tokens=1024,

tools=[...], messages=messages

)

print(final.content[0].text)

# "The weather in Prague is 12°C and partly cloudy."

5. Complete Round-Trip Loop

In production you don't know how many tool calls Claude will make. Use a while loop that keeps running until stop_reason is "end_turn".

┌──────────────────────────────────────────────────────────────────────┐

│ ROUND-TRIP LOOP FLOW │

└──────────────────────────────────────────────────────────────────────┘

START

│

▼

client.messages.create(tools, messages)

│

▼

stop_reason == "tool_use" ? ──YES──► execute all tool_use blocks

│ append assistant msg

│ append tool_result msg

│ ──────────────────────────────► loop

│

NO (end_turn)

│

▼

Print final text response → DONE

import anthropic

client = anthropic.Anthropic()

TOOLS = [{

"name": "get_weather",

"description": "Get weather for a city.",

"input_schema": {"type": "object", "properties": {

"location": {"type": "string"}

}, "required": ["location"]}

}]

def get_weather(location: str) -> str:

# your real implementation here

return "12°C, partly cloudy"

TOOL_MAP = {"get_weather": get_weather}

def run_agent(user_message: str) -> str:

messages = [{"role": "user", "content": user_message}]

while True:

response = client.messages.create(

model="claude-opus-4-7", max_tokens=1024,

tools=TOOLS, messages=messages

)

# Done — return the final text answer

if response.stop_reason != "tool_use":

return response.content[0].text

# Execute all tool calls in this response

tool_results = []

for block in response.content:

if block.type == "tool_use":

fn = TOOL_MAP[block.name]

result = fn(**block.input)

tool_results.append({

"type": "tool_result",

"tool_use_id": block.id,

"content": result

})

# Append assistant turn + tool results, then loop

messages.append({"role": "assistant", "content": response.content})

messages.append({"role": "user", "content": tool_results})

print(run_agent("What is the weather in Prague?")

6. Multiple & Parallel Tools

Defining Multiple Tools

Pass an array of tool definitions. Claude picks the right one based on the user question and tool descriptions.

TOOLS = [

{"name": "get_weather", "description": "Get weather for a city.", "input_schema": {...)},

{"name": "get_time", "description": "Get current time in a timezone.", "input_schema": {...}},

{"name": "search_web", "description": "Search the web for a query.", "input_schema": {...}}

]

Parallel Tool Use

When asked "What's the weather in Prague AND Vienna?", Claude calls both get_weather tools simultaneously in a single response. All tool_use blocks appear in one response.content list.

User: "Weather in Prague AND Vienna?"

Claude response.content:

┌────────────────────────────────────────────────────────────────────┐

│ ToolUseBlock(id="toolu_01", name="get_weather", │

│ input={"location": "Prague"}) │

│ ToolUseBlock(id="toolu_02", name="get_weather", │

│ input={"location": "Vienna"}) │

└────────────────────────────────────────────────────────────────────┘

Your tool_results (all in ONE user message):

┌────────────────────────────────────────────────────────────────────┐

│ {"type": "tool_result", "tool_use_id": "toolu_01", "content": …}│

│ {"type": "tool_result", "tool_use_id": "toolu_02", "content": …}│

└────────────────────────────────────────────────────────────────────┘

# Collect ALL tool results into one user message

tool_results = []

for block in response.content:

if block.type == "tool_use":

result = execute_tool(block.name, block.input)

tool_results.append({

"type": "tool_result",

"tool_use_id": block.id,

"content": result

})

# ALL results go into a SINGLE user message

messages.append({"role": "assistant", "content": response.content})

messages.append({"role": "user", "content": tool_results}) # ← one message, many results

Note: To disable parallel tool use and force one call at a time, add disable_parallel_tool_use=True to client.messages.create().

7. tool_choice — Controlling Tool Selection

The tool_choice parameter tells Claude how to decide whether and which tool to use.

Value

Behavior

auto (default)

Claude decides whether to call a tool or respond with text

any

Claude MUST call a tool — it picks which one

{"type": "tool", "name": "x"}

Claude MUST call the specific named tool

none

Claude cannot use any tools — responds with text only

# Default — Claude decides

response = client.messages.create(

model="claude-opus-4-7", max_tokens=1024, tools=TOOLS,

tool_choice={"type": "auto"}, # default, can omit

messages=messages

)

# Force a specific tool

response = client.messages.create(

model="claude-opus-4-7", max_tokens=1024, tools=TOOLS,

tool_choice={"type": "tool", "name": "get_weather"},

messages=messages

)

# Must use SOME tool, Claude picks which

response = client.messages.create(

model="claude-opus-4-7", max_tokens=1024, tools=TOOLS,

tool_choice={"type": "any"},

messages=messages

)

8. Error Handling

When your tool fails, send back is_error: true. Claude will acknowledge the failure and may retry with different arguments or tell the user it cannot complete the task.

Returning an Error Result

try:

result = get_weather(block.input["location"])

tool_results.append({

"type": "tool_result",

"tool_use_id": block.id,

"content": result,

"is_error": False

})

except Exception as e:

tool_results.append({

"type": "tool_result",

"tool_use_id": block.id,

"content": str(e),

"is_error": True

})

Tool Result Content Variants

# Plain string (most common)

{"type": "tool_result", "tool_use_id": block.id, "content": "12°C"}

# Rich content — text + image

{"type": "tool_result", "tool_use_id": block.id,

"content": [

{"type": "text", "text": "Chart data below"},

{"type": "image", "source": {"type": "base64", "media_type": "image/png", "data": "..."}}

]}

# Acknowledgment only (no useful content to return)

{"type": "tool_result", "tool_use_id": block.id, "content": None}

Pattern 2 — Email Sending Tool

EMAIL_TOOL = {

"name": "send_email",

"description": "Send an email. Use only when user explicitly asks to send.",

"input_schema": {

"type": "object",

"properties": {

"to": {"type": "string", "description": "Recipient email address"},

"subject": {"type": "string"},

"body": {"type": "string"}

},

"required": ["to", "subject", "body"]

}

}

Pattern 3 — Structured Data Extraction

Force tool use with tool_choice to extract structured data from unstructured text — Claude fills in the schema instead of calling a function.

EXTRACT_TOOL = {

"name": "extract_person",

"description": "Extract person details from text.",

"input_schema": {

"type": "object",

"properties": {

"name": {"type": "string"},

"age": {"type": "integer"},

"email": {"type": "string"}

},

"required": ["name"]

}

}

response = client.messages.create(

model="claude-opus-4-7", max_tokens=256,

tools=[EXTRACT_TOOL],

tool_choice={"type": "tool", "name": "extract_person"}, # force it

messages=[{"role": "user", "content": "John Doe, 34, john@mail.com"}]

)

# Get structured data directly — no need to run anything

data = response.content[0].input

print(data) # {"name": "John Doe", "age": 34, "email": "john@mail.com"}

Note: Structured extraction is a common interview topic — Claude fills the JSON schema without any real function being called.

10. Quick Reference

Message Conversation Structure

messages = [

{"role": "user", "content": "What is the weather in Prague?"},

{"role": "assistant", "content": [ToolUseBlock(...)]}, ← turn 1

{"role": "user", "content": [{"type": "tool_result",...}]},

{"role": "assistant", "content": [TextBlock("It is 12°C…")]}, ← final

]

Rule: roles must alternate user → assistant → user → assistant…

Rule: tool_result messages always have role "user"

Rule: all tool results for one turn go in ONE user message

Common Mistakes

Mistake

Fix

Forgetting to append assistant message before tool_result

Always: messages.append({"role": "assistant", "content": response.content})

Sending each tool result as a separate user message

All tool_results for one turn go in ONE user message as a list

tool_use_id mismatch

Copy block.id exactly — Claude will reject a wrong ID

Not looping — assuming one tool call is always enough

Use a while loop checking stop_reason every time

Vague tool descriptions

Write 2-4 sentences explaining what, when, and any caveats

Putting required fields in properties but not in "required" array

JSON Schema: optional fields in properties, mandatory ones also in "required"

stop_reason Values

stop_reason

Meaning

Action

"end_turn"

Claude finished naturally

Read response.content[0].text — done

"tool_use"

Claude wants to call a tool

Execute tools, send results, loop again

"max_tokens"

Output was cut off

Increase max_tokens or split the task

"stop_sequence"

Hit a custom stop sequence

Check your stop_sequences parameter
