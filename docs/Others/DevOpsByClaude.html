1. Introduction to DevOps

DevOps is a cultural and technical movement that merges software Development (Dev) and IT Operations (Ops) to shorten the systems development lifecycle and deliver features, fixes, and updates frequently and reliably.

Before DevOps, development and operations teams worked in silos: developers wrote code and 'threw it over the wall' to operations, causing slow releases, blame-shifting, and fragile systems. DevOps breaks these silos.

Shift Left Principle

Shift Left means moving testing, security, and quality checks earlier in the pipeline — closer to the developer — rather than waiting until deployment. The cost of fixing a bug grows exponentially the later it is found.

7. Quick Reference — Key Terms

Term

Definition

CI (Continuous Integration)

Automatically build and test every code commit

CD (Continuous Delivery)

Every passing build is releasable; deployment is a business decision

CD (Continuous Deployment)

Every passing build automatically deploys to production

IaC (Infrastructure as Code)

Manage cloud/server resources with version-controlled configuration files

Container

Isolated, portable runtime unit packaging app + dependencies (shares OS kernel)

Image

Immutable blueprint for a container (built from a Dockerfile)

Orchestration

Automated management of containers: scheduling, scaling, healing

SRE (Site Reliability Eng.)

Applies software engineering to operations; defines SLOs/SLIs/error budgets

SLA (Service Level Agreement)

Contract with customer — minimum guaranteed uptime (e.g. 99.9%)

SLO (Service Level Objective)

Internal reliability target (e.g. 99.95% uptime)

SLI (Service Level Indicator)

Measured metric used to evaluate SLO (e.g. actual uptime %)

Error Budget

Remaining tolerance for downtime before SLO is breached (SLO − actual uptime)

Blue/Green Deployment

Two identical environments; flip traffic instantly between old and new

Canary Release

Route a small % of traffic to new version before full rollout

Feature Flag

Toggle application features at runtime without redeploying code

GitOps

Git is the single source of truth; changes reconciled automatically to target state

Toil

Manual, repetitive, automatable work that scales linearly with service growth

MTTR (Mean Time to Recover)

Average time from incident detection to service restoration

MTTD (Mean Time to Detect)

Average time to discover an incident after it begins

Post-mortem

Blameless analysis after an incident to find root cause and prevent recurrence

Immutable Infrastructure

Never patch running servers; replace them with new images entirely

Shift Left

Move testing/security earlier in the pipeline, closer to the developer

Platform Engineering

Build internal developer platforms (IDPs) to reduce cognitive load on devs

FinOps

Practices and culture to manage cloud costs collaboratively across eng/finance
