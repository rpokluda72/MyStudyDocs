1. What Are Skills?

Skills are collections of instructions, scripts, and resources that Claude dynamically loads to enhance its performance on specialized tasks. They enable Claude to complete specific workflows repeatably — from applying brand guidelines to automating deployments.

Think of a skill as a "procedure card" you hand Claude: it reads it when needed, follows the steps, and puts it away when done. Unlike CLAUDE.md content (always loaded), skills load only when invoked, so large reference material costs nothing until it is needed.

2. Creating Your First Skill

Every skill is a directory containing a SKILL.md file. The directory name becomes the /command you type. The SKILL.md has two parts: YAML frontmatter between --- markers, and a Markdown body with the instructions.

Minimal SKILL.md Structure

---
name: my-skill
description: What this skill does and when to use it.
---
## Instructions
1. Step one
2. Step two
3. Step three

Step-by-Step: Create a Summarize-Changes Skill

This skill summarizes your uncommitted git changes and flags risky edits. Claude loads it automatically when you ask about your changes, or you can invoke it with /summarize-changes.

# Step 1: create the skill directory (personal — works across all projects)
mkdir -p ~/.claude/skills/summarize-changes
# Step 2: save as ~/.claude/skills/summarize-changes/SKILL.md
---
description: Summarizes uncommitted changes and flags anything risky.
  Use when the user asks what changed, wants a commit message,
  or asks to review their diff.
---
## Current changes
!`git diff HEAD`         ← dynamic context injection (runs before Claude sees the skill)
## Instructions
Summarize the changes above in 2-3 bullet points.
List any risks: missing error handling, hardcoded values, tests that need updating.
If the diff is empty, say there are no uncommitted changes.
# Step 3: test it — open a git project and ask Claude:
What did I change?
# or invoke directly:
/summarize-changes

The best skills: address one specific repeatable task · include clear step-by-step instructions · provide examples of expected output · define when to use them · stay focused — one workflow per skill.

3. Frontmatter Reference

YAML frontmatter between --- markers configures skill behavior. Only description is recommended — all other fields are optional.

Pre-approve Tools — allowed-tools

Grant Claude permission to use specific tools without prompting when this skill is active.

---
name: commit
description: Stage and commit current changes.
disable-model-invocation: true
allowed-tools: Bash(git add *) Bash(git commit *) Bash(git status *)
---
Stage all changes and create a conventional commit message.

Note: allowed-tools grants extra permissions; it does not restrict tools. Your global permission settings still apply to everything else.

4. Skill Directory Structure

A skill is a directory. SKILL.md is the only required file. Add supporting files to keep SKILL.md concise — Claude loads them only when referenced.

Typical Layout

my-skill/

├── SKILL.md ← required — main instructions & navigation

├── reference.md ← detailed API docs — loaded when needed

├── examples.md ← sample inputs/outputs

└── scripts/

└── helper.py ← script Claude can execute (not loaded as text)

Reference Supporting Files from SKILL.md

---
name: code-review
description: Review code for quality, security, and style.
---
## Instructions
Review the provided code following our standards.
## Resources
- Full style guide: see [reference.md](reference.md)
- Example reviews:  see [examples.md](examples.md)
- Lint script:      run scripts/lint.py on changed files

Note: Keep SKILL.md under 500 lines. Move large reference content to separate files.

ZIP Packaging (for upload)

When packaging a skill for organization upload, the ZIP must have the skill folder at the root:

  my-skill.zip                                                             
  └── my-skill/           ← folder name must match the skill name         
      ├── SKILL.md                                                         
      └── resources/                                                       
          └── reference.md                                                 
                                                                           
  ✗  Wrong: SKILL.md at zip root (no containing folder)                   
  ✗  Wrong: my-skill/ nested inside another folder                        
  ✓  Correct: my-skill/ is the zip root level

Live Change Detection

Claude Code watches skill directories for file changes. Editing or adding a SKILL.md takes effect immediately in the current session — no restart needed. Exception: if you create a brand-new skills/ directory that did not exist when the session started, restart Claude Code once.

5. Advanced Patterns

Dynamic Context Injection — !`command`

The !`command` syntax runs a shell command before Claude sees the skill. The output replaces the placeholder, so Claude works with actual live data rather than guessing.

---
name: pr-summary
description: Summarize the current pull request.
context: fork
agent: Explore
allowed-tools: Bash(gh *)
---
## Pull request context
!`gh pr diff`                 ← runs NOW, output inlined before Claude reads skill
!`gh pr view --comments`
!`gh pr diff --name-only`
## Your task
Summarize the changes above. List affected areas and any risks.

Note: Inline !`command` is recognized only when ! appears at the start of a line. For multi-line commands use a fenced block opened with ```!.

Passing Arguments — $ARGUMENTS

---
name: fix-issue
description: Fix a GitHub issue by number.
argument-hint: [issue-number]
disable-model-invocation: true
---
Fix GitHub issue $ARGUMENTS following our coding standards.
1. Read the issue description
2. Implement the fix
3. Write or update tests
4. Create a commit
# Invoke with an argument:
/fix-issue 123
# → Claude receives: "Fix GitHub issue 123 following our coding standards."

Named & Indexed Arguments

---
name: migrate-component
description: Migrate a component between frameworks.
arguments: component from_framework to_framework
---
Migrate the $component component from $from_framework to $to_framework.
Preserve all existing behavior and tests.
# Indexed shorthand ($0, $1, $2 = first, second, third argument):
Migrate the $0 component from $1 to $2.
# Usage:
/migrate-component SearchBar React Vue

Available String Substitutions

Variable

Description

$ARGUMENTS

All arguments passed when invoking the skill as a single string

$ARGUMENTS[N]

Argument at 0-based index — $ARGUMENTS[0] = first, $ARGUMENTS[1] = second

$N

Shorthand for $ARGUMENTS[N] — $0 = first arg, $1 = second

$name

Named argument declared in the arguments frontmatter field

${CLAUDE_SESSION_ID}

Current session ID — useful for log files or session-specific output

${CLAUDE_EFFORT}

Current effort level: low, medium, high, xhigh, or max

${CLAUDE_SKILL_DIR}

Directory of the SKILL.md file — use to reference bundled scripts reliably

Run in a Subagent — context: fork

Add context: fork to run the skill in an isolated context. The skill content becomes the subagent's prompt. It has no access to your conversation history.

---
name: deep-research
description: Research a codebase topic thoroughly.
context: fork
agent: Explore   ← read-only agent, optimized for searching
---
Research $ARGUMENTS thoroughly:
1. Find relevant files using Glob and Grep
2. Read and analyze the code
3. Summarize findings with specific file references

Note: context: fork only makes sense for skills with explicit tasks, not for reference/knowledge skills without a clear action.

6. Using Skills

Enable Code Execution First

Skills require code execution to be enabled. Without it, skills are unavailable.

Plan

Where to enable

Free / Pro / Max

Settings → Capabilities → toggle on "Code execution and file creation"

Team / Enterprise

Organization settings → Capabilities → "Code execution and file creation"

Access Skills — Customize > Skills

After enabling code execution, go to Customize > Skills. You will see skills organized into three categories:

  Customize > Skills                                                       
  ┌──────────────────────────────────────────────────────────────────────┐
  │  Personal skills       ← your own uploaded or created skills         │
  │  Shared with you       ← colleague-shared skills (grayed until ON)   │
  │  Organization skills   ← owner-provisioned + member-published skills │
  └──────────────────────────────────────────────────────────────────────┘
  Each skill has a toggle to enable/disable it individually.

Upload a Custom Skill

# 1. Package your skill as a ZIP
#    my-skill/ folder must be at the ZIP root — see Section 4
# 2. In Claude Code:
Customize → Skills → "+" → "Create skill" → "Upload a skill"
Select your .zip file → skill appears in Personal skills immediately

Invoking Skills

# Auto-invocation — Claude decides based on description
Review my code for security issues      ← Claude loads /code-review automatically
# Direct invocation — type / followed by skill name
/summarize-changes
/fix-issue 123
/deploy production
# With arguments:
/migrate-component SearchBar React Vue

Delete a Personal Skill

Customize → Skills → open skill → "..." menu → Delete
# Note: you can only DELETE personal skills.
# Organization-provisioned skills can only be toggled off, not deleted by users.

7. Organization Management (Team & Enterprise)

Organization owners can provision skills to all members from the admin panel. Provisioned skills appear automatically in every member's Customize > Skills — no manual upload required.

Prerequisites

Organization settings → Capabilities
  ✓ Enable "Code execution and file creation"
Organization settings → Skills
  ✓ Enable "Skills"
# Both must be ON before org-level skill management is available.
# Skills require code execution — if code exec is off, skills are unavailable.

Provision a Skill to All Members

  Organization settings → Skills → "+ Add"                                
  │                                                                        
  ▼                                                                        
  Select a .zip file containing your SKILL.md                             
  │                                                                        
  ▼                                                                        
  Skill immediately appears in ALL members' Organization skills section   
  Enabled by default (users can toggle off individually)

Skill Sharing Options

In addition to top-down provisioning, you can allow members to share skills they built with each other. Both options are OFF by default.

Feature

Note: There is no approval workflow for org-wide sharing. If you enable "Share with organization", any member can publish to the directory without review. Consider directing members to submit skills to owners for formal provisioning instead.

Shared Skills Are Read-Only

Recipients can enable and use a shared skill but cannot edit its contents. Shared skills appear grayed out in the Shared with you section until the recipient toggles them on.

Remove a Provisioned Skill

Organization settings → Skills → locate skill → Remove
# Once removed, the skill disappears from all members' skills lists.
# Only owners can add or remove organization-wide skills.
# Individual users cannot delete provisioned skills — they can only toggle off.

Audit & Compliance

Skill sharing activities are logged as role_assignment events in both audit logs and the Compliance API. Each entry captures who shared, with whom, and whether it was peer-to-peer or org-wide.

Note: The audit log records share events only — it does not capture the contents of shared skills.

8. Skill Visibility & Permissions

skillOverrides — Control Visibility from Settings

The skillOverrides setting lets you control skill visibility without editing the SKILL.md file — useful for shared project skills or MCP-provided skills. The /skills menu writes this for you: highlight a skill and press Space to cycle states.

# .claude/settings.local.json
{
    "skillOverrides": {
        "legacy-context": "name-only",  ← listed to Claude by name only, no description
        "deploy":         "off"         ← completely hidden from Claude AND / menu
        "code-review":    "on"          ← default — name + description visible
    }
}

Name only

Hidden

Yes

Control Which Skills Claude Can Call — Permissions

# Deny ALL skill tool calls (Claude cannot invoke any skill):
Add to deny rules:   Skill
# Allow only specific skills:
Skill(commit)
Skill(review-pr *)
# Deny specific skills:
Skill(deploy *)
# Syntax:
Skill(name)      ← exact match
Skill(name *)    ← prefix match with any arguments

Note: Plugin skills are not affected by skillOverrides — manage those through /plugin instead.

Skill Description Budget

All skill descriptions load into context so Claude knows what is available. If you have many skills, descriptions get shortened to fit the budget (default: 1% of model context window). Skills you invoke most keep their full descriptions.

# Diagnose budget overflow:
/doctor
# Raise the budget in settings:
{
    "skillListingBudgetFraction": 0.02   ← 2% of context window
    "maxSkillDescriptionChars": 1536   ← per-skill cap (default)
}
# Or free budget: set low-priority skills to "name-only" in skillOverrides
