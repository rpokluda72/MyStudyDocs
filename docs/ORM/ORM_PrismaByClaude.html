1. Introduction

Prisma (2019) is a schema-first ORM that uses a declarative schema language (Prisma SDL) as the single source of truth. It auto-generates a fully-typed PrismaClient at build time, delivering outstanding TypeScript auto-complete for queries without needing extra type definitions.

Key Concepts

  • schema.prisma — defines models, relations, and DB connection in Prisma SDL.
  • PrismaClient — auto-generated, fully-typed query builder; one shared instance per process.
  • prisma migrate — manages schema migrations via generated SQL files checked into git.
  • Prisma Studio — browser GUI to inspect and edit data, started with npx prisma studio.
  • @relation() — required on every relation field; defines FK fields and references explicitly.

When to Use

  • TypeScript projects where developer experience and end-to-end type safety are paramount.
  • Teams that want a single schema file as the source of truth for both DB and types.
  • Rapid development where Prisma Studio for live data inspection adds value.

When NOT to Use

  • Projects needing deep QueryBuilder flexibility for very complex aggregations.
  • Environments where running npx prisma generate at build time is not feasible.

2. Installation & Setup

Install Packages

npm install @prisma/client
npm install --save-dev prisma
# Initialise schema.prisma + .env
npx prisma init --datasource-provider mysql
.env File
# .env
DATABASE_URL="mysql://root:secret@localhost:3306/blog_db?charset=utf8mb4"

PrismaClient Singleton

Create one shared instance to avoid exhausting the connection pool on hot reloads:

// lib/prisma.ts
import { PrismaClient } from '@prisma/client';
const globalForPrisma = globalThis as unknown as { prisma?: PrismaClient };
export const prisma =
  globalForPrisma.prisma ??
  new PrismaClient({ log: ['error'] });
if (process.env.NODE_ENV !== 'production') {
  globalForPrisma.prisma = prisma;
}

3. Schema Definition

All models live in a single schema.prisma file. Relations use @relation() with explicit foreign-key and reference fields.

Datasource & Generator

// schema.prisma
datasource db {
  provider = "mysql"
  url      = env("DATABASE_URL")
}
generator client {
  provider = "prisma-client-js"
}

User Model

model User {
  id           Int       @id @default(autoincrement())
  username     String    @unique @db.VarChar(50)
  email        String    @unique @db.VarChar(255)
  passwordHash String    @db.VarChar(255)
  createdAt    DateTime  @default(now())
  posts        Post[]
  comments     Comment[]
  @@map("users")
}

Post Model

model Post {
  id        Int       @id @default(autoincrement())
  title     String    @db.VarChar(255)
  content   String    @db.Text
  status    Status    @default(draft)
  authorId  Int
  author    User      @relation(fields: [authorId], references: [id])
  comments  Comment[]
  tags      Tag[]     @relation("PostTags")
  createdAt DateTime  @default(now())
  updatedAt DateTime  @updatedAt
  @@map("posts")
}
enum Status {
  draft
  published
}

Comment Model

model Comment {
  id        Int      @id @default(autoincrement())
  content   String   @db.Text
  postId    Int
  post      Post     @relation(fields: [postId],   references: [id])
  authorId  Int
  author    User     @relation(fields: [authorId], references: [id])
  createdAt DateTime @default(now())
  @@map("comments")
}

Tag Model

model Tag {
  id    Int    @id @default(autoincrement())
  name  String @unique @db.VarChar(100)
  posts Post[] @relation("PostTags")
  @@map("tags")
}
// Prisma manages the post_tags junction table automatically.
// For an explicit junction model use:
//   model PostTag { postId Int; tagId Int; @@id([postId, tagId]) }

Generate the Client

npx prisma generate

    status:   'draft',

const post = await prisma.post.findUnique({ where: { id: 42 } });

  where:   { status: 'published' },

const updated = await prisma.post.update({
  where: { id: 42 },

5. Querying

WHERE with Multiple Conditions

const posts = await prisma.post.findMany({
  where: {
    authorId: 5,
    status:   'published',
  },
  orderBy: { createdAt: 'desc' },
});

Pagination

const PAGE     = 2;
const PER_PAGE = 10;
const [posts, total] = await prisma.$transaction([
  prisma.post.findMany({
    where:   { status: 'published' },
    orderBy: { createdAt: 'desc' },
    take:    PER_PAGE,
    skip:    (PAGE - 1) * PER_PAGE,
  }),
  prisma.post.count({ where: { status: 'published' } }),
]);
console.log(`Page ${PAGE} of ${Math.ceil(total / PER_PAGE)}`);

Select Specific Fields

const posts = await prisma.post.findMany({
  where:  { status: 'published' },
  select: { title: true, createdAt: true },
});

LIKE Search (contains)

const posts = await prisma.post.findMany({
  where: { title: { contains: 'prisma' } },
});

6. Associations

Load Posts with Author (1:N)

const posts = await prisma.post.findMany({
  where:   { status: 'published' },
  include: { author: { select: { username: true, email: true } } },
});
posts.forEach(p => console.log(p.title, p.author.username));

Nested Create — Post with First Comment

const post = await prisma.post.create({
  data: {
    title:    'New Post',
    content:  'Content here...',
    status:   'draft',
    authorId: 1,
    comments: {
      create: { content: 'First comment!', authorId: 2 },
    },
  },
  include: { comments: true },
});

Many-to-Many — Post with Tags

const post = await prisma.post.findUnique({
  where:   { id: 1 },
  include: { tags: true },
});
// Connect an existing tag
await prisma.post.update({
  where: { id: 1 },
  data:  { tags: { connect: { id: 3 } } },
});

7. Migrations

CLI Commands

CREATE TABLE `users` (
  `id`           INT UNSIGNED NOT NULL AUTO_INCREMENT,
  `username`     VARCHAR(50)  NOT NULL,
  `email`        VARCHAR(255) NOT NULL,

8. Transactions

Prisma provides two transaction forms. Interactive transactions ($transaction with callback) are the most flexible and recommended when operations depend on each other's results:

Interactive Transaction

const { post, comment } = await prisma.$transaction(async (tx) => {
  const post = await tx.post.create({
    data: {
      title:    'Atomic Post',
      content:  'Created inside a transaction.',
      status:   'draft',
      authorId: 1,
    },
  });
  const comment = await tx.comment.create({
    data: {
      content:  'First comment on the new post.',
      postId:   post.id,
      authorId: 2,
    },
  });
  return { post, comment };
});

Sequential (Array) Transaction

For independent operations that do not need each other's results:

const [newTag, postCount] = await prisma.$transaction([
  prisma.tag.create({ data: { name: 'nodejs' } }),
  prisma.post.count({ where: { status: 'published' } }),
]);

9. Raw / Advanced Queries

Top 5 authors by published post count using $queryRaw:

import { Prisma } from '@prisma/client';
const results = await prisma.$queryRaw<
  Array<{ username: string; email: string; postCount: bigint }>
>(Prisma.sql`
  SELECT u.username, u.email, COUNT(p.id) AS postCount
    FROM users  u
    JOIN posts  p ON p.authorId = u.id
   WHERE p.status = 'published'
   GROUP BY u.id
   ORDER BY postCount DESC
   LIMIT 5
`);
// COUNT returns bigint in raw queries — convert with Number()
results.forEach(r => console.log(r.username, Number(r.postCount)));

Using groupBy (Prisma API)

const grouped = await prisma.post.groupBy({
  by:      ['authorId'],
  where:   { status: 'published' },
  _count:  { id: true },
  orderBy: { _count: { id: 'desc' } },
  take:    5,
});
grouped.forEach(g => console.log(g.authorId, g._count.id));
