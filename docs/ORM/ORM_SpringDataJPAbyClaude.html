1. Introduction

Spring Data JPA is the recommended ORM layer for Spring Boot applications. It sits on top of JPA (Java Persistence API — a specification) which is implemented by Hibernate. Understanding the three-layer stack is key to debugging and performance tuning.

Three-Layer Stack

  Your Service / Controller
         │
         ▼
  ┌─────────────────────────────────────────────┐
  │            Spring Data JPA                  │
  │  PostRepository extends JpaRepository<>     │
  │  findByStatus()  findByTitle...()  @Query   │
  └─────────────────────────┬───────────────────┘
                            │
                            ▼
  ┌─────────────────────────────────────────────┐
  │         JPA  (javax.persistence / jakarta)  │
  │  EntityManager  │  JPQL  │  Criteria API    │
  │  @Entity  @Table  @Column  @Id  @OneToMany  │
  └─────────────────────────┬───────────────────┘
                            │
                            ▼
  ┌─────────────────────────────────────────────┐
  │       Hibernate  (JPA Provider)             │
  │  Session  │  HQL  │  SQL Generation         │
  │  1st-level cache  │  2nd-level cache (opt.) │
  └─────────────────────────┬───────────────────┘
                            │
                            ▼
                      MySQL Database

Spring Data JPA → JPA → Hibernate → MySQL

Layer Responsibilities

Spring Data JPA

Adds repository abstraction — auto-generates CRUD + query implementations at runtime. No SQL or JPQL needed for common operations.

JPA (specification)

Defines @Entity, @Table, @Column, @Id, EntityManager, JPQL, Criteria API. jakarta.persistence (formerly javax.persistence) package.

Hibernate

JPA implementation. Manages Session (wraps EntityManager), 1st-level cache per transaction, optional 2nd-level cache, SQL generation, and schema DDL.

Key Concepts

  • Entity — @Entity class that maps to a DB table; instances are managed by EntityManager.
  • Repository — interface extending JpaRepository<T, ID>; Spring generates the implementation.
  • EntityManager — JPA's core API: persist(), find(), merge(), remove(), createQuery().
  • JPQL — object-oriented query language; operates on entity names/fields, not table/column names.
  • PersistenceContext — first-level cache per transaction; tracks entity state changes automatically.
  • Lazy / Eager loading — controls when related entities are fetched from the DB.

When to Use

  • Standard CRUD-heavy Spring Boot apps with relational data and clear domain model.
  • Projects using NestJS or the broader Spring ecosystem (Security, MVC, Batch, etc.).
  • When derived query methods and @Query cover most use cases cleanly.

When NOT to Use

  • Reporting-heavy apps with very complex multi-join queries — consider JOOQ or raw JDBC.
  • High-performance bulk operations — Hibernate adds overhead vs. JDBC batch inserts.

ddl-auto Values

none

Do nothing. Use with Flyway/Liquibase in production.

validate

Validate schema matches entities on startup — fails fast if there is drift.

update

Alter tables to match entities. Never use in production — can lose data.

create

Drop and re-create tables on startup. Development / test only.

create-drop

Create on startup, drop on shutdown. Integration tests.

Auto-Configuration Beans

Spring Boot auto-configures the following beans — you rarely need to declare them manually:

  • DataSource — HikariCP connection pool from spring.datasource.* properties.
  • LocalContainerEntityManagerFactoryBean — scans @Entity classes, creates EntityManagerFactory.
  • JpaTransactionManager — integrates @Transactional with JPA EntityManager lifecycle.

3. Schema Definition (Entities)

Each JPA entity is a Java class annotated with @Entity. The class is mapped to a table; fields are mapped to columns. Lombok annotations (@Getter, @Setter, @NoArgsConstructor) eliminate boilerplate. All entities use IDENTITY strategy for auto-increment PKs.

Status Enum

// Status.java
public enum Status {
    DRAFT, PUBLISHED
}

User Entity

// User.java
import jakarta.persistence.*;
import lombok.*;
import org.hibernate.annotations.CreationTimestamp;
import java.time.LocalDateTime;
import java.util.*;
@Entity
@Table(name = "users")
@Getter @Setter
@NoArgsConstructor
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    @Column(length = 50, unique = true, nullable = false)
    private String username;
    @Column(length = 255, unique = true, nullable = false)
    private String email;
    @Column(length = 255, nullable = false)
    private String passwordHash;
    @CreationTimestamp
    private LocalDateTime createdAt;
    @OneToMany(mappedBy = "author", cascade = CascadeType.ALL, fetch = FetchType.LAZY)
    private List<Post> posts = new ArrayList<>();
    @OneToMany(mappedBy = "author", cascade = CascadeType.ALL, fetch = FetchType.LAZY)
    private List<Comment> comments = new ArrayList<>();
}

Post Entity

// Post.java
import jakarta.persistence.*;
import lombok.*;
import org.hibernate.annotations.*;
import java.time.LocalDateTime;
import java.util.*;
@Entity
@Table(name = "posts")
@Getter @Setter
@NoArgsConstructor
public class Post {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    @Column(length = 255, nullable = false)
    private String title;
    @Column(columnDefinition = "TEXT", nullable = false)
    private String content;
    @Enumerated(EnumType.STRING)
    @Column(nullable = false)
    private Status status = Status.DRAFT;
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "authorId", nullable = false)
    private User author;
    @OneToMany(mappedBy = "post", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<Comment> comments = new ArrayList<>();
    // post_tags junction table managed by Hibernate
    @ManyToMany
    @JoinTable(
        name = "post_tags",
        joinColumns        = @JoinColumn(name = "postId"),
        inverseJoinColumns = @JoinColumn(name = "tagId")
    )
    private Set<Tag> tags = new HashSet<>();
    @CreationTimestamp
    private LocalDateTime createdAt;
    @UpdateTimestamp
    private LocalDateTime updatedAt;
}

Comment Entity

// Comment.java
@Entity
@Table(name = "comments")
@Getter @Setter @NoArgsConstructor
public class Comment {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    @Column(columnDefinition = "TEXT", nullable = false)
    private String content;
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "postId", nullable = false)
    private Post post;
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "authorId", nullable = false)
    private User author;
    @CreationTimestamp
    private LocalDateTime createdAt;
}

4. CRUD Operations

Define a repository interface — Spring generates the implementation at startup:

// PostRepository.java
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.stereotype.Repository;
@Repository
public interface PostRepository extends JpaRepository<Post, Long> {
    // Additional query methods go here (Section 5)
}

JpaRepository<T, ID> already provides: save(), findById(), findAll(), deleteById(), count(), existsById(), and paginated / sorted variants.

Create

Post post = new Post();
post.setTitle("Getting Started with Spring Data JPA");
post.setContent("Spring Data JPA makes persistence easy...");
post.setStatus(Status.DRAFT);
post.setAuthor(userRepository.getReferenceById(L));  // no DB hit
Post saved = postRepository.save(post);
System.out.println(saved.getId());  // auto-generated PK

Find by Primary Key

Optional<Post> opt = postRepository.findById(L);
Post post = opt.orElseThrow(() -> new EntityNotFoundException("Post not found"));

Find All

List<Post> all = postRepository.findAll();
// Sorted
List<Post> sorted = postRepository.findAll(
    Sort.by(Sort.Direction.DESC, "createdAt")
);

Update

// Load the entity first — Hibernate tracks changes automatically (dirty checking)
Post post = postRepository.findById(L).orElseThrow();
post.setTitle("Updated Title");
post.setStatus(Status.PUBLISHED);
// save() is optional if called inside a @Transactional method — dirty checking fires on commit
postRepository.save(post);

Delete

postRepository.deleteById(L);
// Or load + delete (triggers cascades)
Post post = postRepository.findById(L).orElseThrow();
postRepository.delete(post);

getReferenceById vs findById

findById(id)

Always hits the DB. Returns Optional<T>. Use when you need the entity's data.

getReferenceById(id)

Returns a proxy — no DB hit. Use when you only need a reference for a FK (e.g., setting post.setAuthor(userRepo.getReferenceById(1L))).

5. Querying

Derived Query Methods

Spring Data generates SQL from method names automatically — no implementation needed:

public interface PostRepository extends JpaRepository<Post, Long> {
    // WHERE status = ?
    List<Post> findByStatus(Status status);
    // WHERE author.id = ? AND status = ? ORDER BY createdAt DESC
    List<Post> findByAuthorIdAndStatusOrderByCreatedAtDesc(
        Long authorId, Status status
    );
    // WHERE title LIKE %?%  (case-insensitive)
    List<Post> findByTitleContainingIgnoreCase(String keyword);
    // EXISTS query
    boolean existsByTitleAndAuthorId(String title, Long authorId);
    // COUNT
    long countByStatus(Status status);
}

Pagination with Pageable

// Repository method
Page<Post> findByStatus(Status status, Pageable pageable);
// Caller
Pageable page = PageRequest.of(
    1,                                  // page index (0-based)
    10,                                 // page size
    Sort.by("createdAt").descending()
);
Page<Post> result = postRepository.findByStatus(Status.PUBLISHED, page);
result.getContent();           // List<Post> for this page
result.getTotalElements();     // total rows matching WHERE
result.getTotalPages();        // total page count
result.hasNext();              // is there a next page?
@Query — JPQL

JPQL uses entity class names and field names (not table/column names):

@Query("SELECT p FROM Post p " +
       "WHERE p.author.id = :authorId AND p.status = :status " +
       "ORDER BY p.createdAt DESC")
List<Post> findPublishedByAuthor(
    @Param("authorId") Long authorId,
    @Param("status")   Status status
);
@Query — Native SQL
@Query(
    value  = "SELECT * FROM posts WHERE title LIKE %:kw% AND status = 'PUBLISHED'",
    nativeQuery = true
)
List<Post> searchByKeywordNative(@Param("kw") String keyword);
@Modifying — UPDATE / DELETE
@Modifying
@Transactional
@Query("UPDATE Post p SET p.status = :status WHERE p.author.id = :authorId")
int publishAllByAuthor(@Param("authorId") Long authorId, @Param("status") Status status);

6. Associations & Fetch Strategy

Fetch Type Defaults

@ManyToOne

EAGER by default — always loaded immediately. Override to LAZY in most cases.

@OneToOne

EAGER by default. Usually override to LAZY.

@OneToMany

LAZY by default — loaded only when accessed.

@ManyToMany

LAZY by default.

Best practice: set ALL associations to FetchType.LAZY and use JOIN FETCH in queries when you need the related data. This avoids unintended DB hits.

N+1 Problem

The N+1 problem is a classic interview topic. It occurs when loading a list of N entities triggers N additional queries to load their associations:

// BAD — triggers 1 query for posts + N queries for each post.author
List<Post> posts = postRepository.findByStatus(Status.PUBLISHED);
posts.forEach(p -> System.out.println(p.getAuthor().getUsername()));  // N extra SELECTs

Fix with JOIN FETCH in JPQL — fetches everything in a single query:

// GOOD — single JOIN query
@Query("SELECT p FROM Post p JOIN FETCH p.author WHERE p.status = :status")
List<Post> findPublishedWithAuthor(@Param("status") Status status);

Load Posts with Author (1:N)

// Repository
@Query("SELECT p FROM Post p JOIN FETCH p.author WHERE p.status = :status " +
       "ORDER BY p.createdAt DESC")
List<Post> findPublishedWithAuthor(@Param("status") Status status);
// Service
List<Post> posts = postRepository.findPublishedWithAuthor(Status.PUBLISHED);
posts.forEach(p -> System.out.println(p.getTitle() + " by " + p.getAuthor().getUsername()));

Cascade Types

PERSIST

Save child when parent is saved.

MERGE

Update child when parent is merged.

REMOVE

Delete child when parent is deleted.

REFRESH

Reload child when parent is refreshed from DB.

DETACH

Detach child when parent is detached from persistence context.

ALL

All of the above — common for @OneToMany parent-owns-child.

orphanRemoval = true (on @OneToMany) deletes child rows when they are removed from the parent's collection, even without explicit CascadeType.REMOVE.

Many-to-Many — Post with Tags

// Add a tag to a post (inside @Transactional)
Post post = postRepository.findById(L).orElseThrow();
Tag  tag  = tagRepository.findByName("java").orElseGet(() -> {
    Tag t = new Tag(); t.setName("java"); return tagRepository.save(t);
});
post.getTags().add(tag);
// Dirty checking inserts into post_tags on commit — no extra save() needed
// Fetch post with tags
@Query("SELECT p FROM Post p JOIN FETCH p.tags WHERE p.id = :id")
Optional<Post> findWithTags(@Param("id") Long id);

In production, never rely on Hibernate's ddl-auto=update. Use Flyway (or Liquibase) to manage schema changes as versioned SQL files in source control.

Flyway vs ddl-auto Comparison

ddl-auto=update

Quick for development; dangerous in production; no history; conflicts on concurrent deploy.

ddl-auto=validate

Good safety net; use with Flyway so schema is already correct before app starts.

Flyway migrate

Production-grade; versioned; repeatable; safe for concurrent deploys; auditable.

Liquibase

XML/YAML/JSON-based alternative to Flyway; more complex but richer diff tooling.

8. Transactions

@Transactional is a Spring AOP proxy — it wraps the method in a transaction that is committed on normal return or rolled back on any RuntimeException (by default).

Basic @Transactional Usage

@Service
public class PostService {
    private final PostRepository    postRepository;
    private final CommentRepository commentRepository;
    // Constructor injection (Lombok @RequiredArgsConstructor)
    @Transactional                          // commit on success, rollback on RuntimeException
    public Post createPostWithComment(CreatePostRequest req, Long authorId) {
        Post post = new Post();
        post.setTitle(req.getTitle());
        post.setContent(req.getContent());
        post.setStatus(Status.DRAFT);
        post.setAuthor(userRepository.getReferenceById(authorId));
        postRepository.save(post);
        Comment comment = new Comment();
        comment.setContent("Initial comment.");
        comment.setPost(post);
        comment.setAuthor(userRepository.getReferenceById(authorId));
        commentRepository.save(comment);
        return post;
        // Both inserts committed here; if anything throws, both roll back
    }
    @Transactional(readOnly = true)         // optimises: no flush, read-only Connection hint
    public Page<Post> getPublishedPosts(Pageable pageable) {
        return postRepository.findByStatus(Status.PUBLISHED, pageable);
    }
}

Propagation Types

REQUIRED (default)

Join existing transaction or start a new one.

REQUIRES_NEW

Always start a new transaction; suspend the outer one.

NESTED

Start a savepoint inside the existing transaction.

SUPPORTS

Join existing if present; run non-transactionally if not.

NOT_SUPPORTED

Suspend existing transaction; run non-transactionally.

MANDATORY

Throw if no existing transaction.

NEVER

Throw if a transaction is active.

Isolation Levels

READ_UNCOMMITTED

Can read uncommitted data (dirty reads). Not safe.

READ_COMMITTED

Default in most DBs. Prevents dirty reads.

REPEATABLE_READ

MySQL default. Prevents dirty + non-repeatable reads.

SERIALIZABLE

Fully serialized. Prevents phantom reads. Slowest.

@Transactional(isolation = Isolation.READ_COMMITTED)
public void someMethod() { ... }

Rollback Rules

// Roll back on checked exception too
@Transactional(rollbackFor = Exception.class)
public void riskyMethod() throws IOException { ... }
// Do NOT roll back on a specific exception
@Transactional(noRollbackFor = OptimisticLockingFailureException.class)
public void retryableMethod() { ... }
@Transactional Self-Invocation Warning

Calling a @Transactional method from within the same class bypasses the AOP proxy — the transaction annotation is ignored. Always inject self or move the method to a separate service bean if you need transactional behaviour on an internal call.

9. Advanced Queries

Top 5 Authors by Published Post Count — JPQL

Use interface-based projections to map aggregate query results to a typed object:

// Projection interface — Spring generates a proxy at runtime
public interface AuthorStats {
    String getUsername();
    String getEmail();
    Long   getPostCount();
}
// Repository
@Query("SELECT u.username AS username, u.email AS email, COUNT(p.id) AS postCount " +
       "FROM User u JOIN u.posts p " +
       "WHERE p.status = :status " +
       "GROUP BY u.id " +
       "ORDER BY postCount DESC")
List<AuthorStats> findTopAuthorsByPostCount(
    @Param("status") Status status,
    Pageable pageable
);
// Caller
Pageable top5 = PageRequest.of(0, 5);
List<AuthorStats> result = postRepository.findTopAuthorsByPostCount(Status.PUBLISHED, top5);
result.forEach(a -> System.out.println(a.getUsername() + ": " + a.getPostCount()));

Native SQL Aggregate

Use @Query(nativeQuery=true) when the JPQL equivalent would be awkward:

@Query(
    value = "SELECT u.username, u.email, COUNT(p.id) AS postCount " +
            "FROM users u " +
            "JOIN posts p ON p.authorId = u.id " +
            "WHERE p.status = 'PUBLISHED' " +
            "GROUP BY u.id ORDER BY postCount DESC LIMIT 5",
    nativeQuery = true
)
List<AuthorStats> findTopAuthorsNative();

Criteria API

The Criteria API is type-safe and dynamic — useful when WHERE conditions are built at runtime:

@Service
public class PostSearchService {
    @PersistenceContext
    private EntityManager em;
    public List<Post> search(String keyword, Status status) {
        CriteriaBuilder  cb    = em.getCriteriaBuilder();
        CriteriaQuery<Post> q  = cb.createQuery(Post.class);
        Root<Post> root        = q.from(Post.class);
        List<Predicate> preds = new ArrayList<>();
        if (keyword != null)
            preds.add(cb.like(cb.lower(root.get("title")),
                              "%" + keyword.toLowerCase() + "%"));
        if (status != null)
            preds.add(cb.equal(root.get("status"), status));
        q.where(preds.toArray(new Predicate[0]));
        q.orderBy(cb.desc(root.get("createdAt")));
        return em.createQuery(q).getResultList();
    }
}

JPA Specifications (Spring Data)

Extend JpaSpecificationExecutor to add Criteria-based queries without boilerplate:

public interface PostRepository extends
        JpaRepository<Post, Long>,
        JpaSpecificationExecutor<Post> {  // adds findAll(Specification, Pageable)
}
// Reusable specification
public class PostSpecs {
    public static Specification<Post> hasStatus(Status s) {
        return (root, query, cb) -> cb.equal(root.get("status"), s);
    }
    public static Specification<Post> titleContains(String kw) {
        return (root, query, cb) ->
            cb.like(cb.lower(root.get("title")), "%" + kw.toLowerCase() + "%");
    }
}
// Usage
Page<Post> page = postRepository.findAll(
    PostSpecs.hasStatus(Status.PUBLISHED).and(PostSpecs.titleContains("jpa")),
    PageRequest.of(0, 10, Sort.by("createdAt").descending())
);

Optimistic Locking

Prevents concurrent updates from overwriting each other — common interview topic:

// Add @Version field to entity
@Version
private Long version;
// Hibernate automatically adds WHERE version = ? to UPDATE.
// If another transaction updated the row first, a
// OptimisticLockingFailureException is thrown.
