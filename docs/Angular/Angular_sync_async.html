Rozdíl mezi synchronním a asynchronním zpracováním

v Angularu (a JavaScriptu obecně) spočívá v tom, kdy a jak se kód provádí a zda při tom blokuje zbytek aplikace.

1. Synchronní kód (Blokující)

  • Jak funguje: Kód se provádí příkaz po příkazu, jeden po druhém. Dokud neskončí aktuální operace, program čeká a nepřejde na další řádek.
  • Vliv na aplikaci: Pokud provádíte náročnou operaci (např. složitý výpočet), zablokuje se celé uživatelské rozhraní. Aplikace zamrzne a uživatel nemůže klikat ani scrollovat.
  • V Angularu: Běžná lokální data, logické operace, matematika nebo manipulace s poli.

2. Asynchronní kód (Neblokující)

  • Jak funguje: Kód se „odloží“ a aplikace běží dál. Jakmile asynchronní operace doběhne, vrátí výsledek a ten se teprve zpracuje.
  • Vliv na aplikaci: Uživatelské rozhraní zůstává plynulé. Prohlížeč totiž nečeká na dokončení úkolu (např. stažení dat z databáze) a plynule vykresluje dál.
  • V Angularu: Komunikace se serverem (HTTP požadavky), práce s formuláři (reaktivní přístup), časovače (setTimeout) nebo čtení souborů. Hlavní nástroj pro síťovou komunikaci (HTTP dotazy). Díky tomu aplikace nezamrzne, uživatel může dál klikat na tlačítka a data z backendu se vykreslí, až dorazí.

Jak vypadá praxe v Angularu?

V Angularu se asynchronní kód nejčastěji řeší pomocí RxJS Observables (v HttpClientu) nebo moderních Promise a syntaxe async/await.

V Angularu je asynchronní chování naprosto klíčové, protože JavaScript (na kterém TypeScript staví) funguje na principu jednoho hlavního vlákna. K zablokování prohlížeče slouží:

  • RxJS (Observables): Základní kámen Angularu. Využívá se pro volání služeb, jako je this.http.get('api/data'). Aplikace nečeká a pokračuje, data se načtou a zobrazí až ve chvíli, kdy server odpoví.

Promise a async/await: Další způsob, jak řešit asynchronní kód a vyhnout se tzv. „callback hell“.

A. HTTP požadavek v Angularu (Asynchronně)

Při načítání dat z API aplikace vyšle požadavek a ihned pokračuje v běhu (vykresluje komponenty). Až server odpoví, data se propasírují do šablony.

import { HttpClient } from '@angular/common/http';
import { Component } from '@angular/core';
@Component({ ... })
export class MujKomponent {
  constructor(private http: HttpClient) {}
  nacistData() {
    // Toto je asynchronní operace
    this.http.get('https://mojedomena.cz').subscribe(data => {
      console.log('Data přišla až nyní:', data);
    });
    console.log('Tento řádek se vypíše HNED, ještě než přijdou data z API!');
  }
}

B. Tradiční ukázka rozdílu (Synchronní vs. Asynchronní)

Synchronní kód:

console.log('1. Krok');
console.log('2. Krok');
console.log('3. Krok');
// Výstup jde přesně popořadě: 1, 2, 3

Asynchronní kód:

console.log('1. Krok');
// Nastavíme odložené provedení (asynchronně)
setTimeout(() => {
  console.log('3. Krok (Provede se se zpožděním)');
}, 1000);
console.log('2. Krok');
// Výstup jde v pořadí: 1, 2, ...a za vteřinu: 3
??? Chci se podívat na konkrétní kód v Angularu (RxJS vs. Promise)

Rozdíl mezi RxJS (Observable) a Promise v Angularu spočívá v tom, že Promise vrátí pouze jednu hodnotu a končí, zatímco Observable je proud dat, který může posílat hodnoty opakovaně a lze ho zrušit.

Zde je ukázka obou přístupů na stejném příkladu (získání dat uživatele z API).

1. Řešení pomocí Promise

Promise se spustí okamžitě při vytvoření a vrátí data pouze jednou.

Služba (Service)

import { HttpClient } from '@angular/common/http';
import { Injectable, inject } from '@angular/core';
import { firstValueFrom } from 'rxjs';
@Injectable({ providedIn: 'root' })
export class UserService {
  private http = inject(HttpClient);
  // Převod z Observable na Promise pomocí firstValueFrom
  getUserPromise(): Promise<any> {
    return firstValueFrom(this.http.get('api/user'));
  }
}

Komponenta (Component)

import { Component, OnInit, inject } from '@angular/core';
import { UserService } from './user.service';
@Component({ selector: 'app-user', template: `{{ user | json }}` })
export class UserComponent implements OnInit {
  private userService = inject(UserService);
  user: any;
  async ngOnInit() {
    try {
      // Kód čeká na tomto řádku, dokud Promise neskončí
      this.user = await this.userService.getUserPromise();
    } catch (error) {
      console.error('Chyba při načítání', error);
    }
  }
}

2. Řešení pomocí RxJS (Observable)

Observable je líný (nespustí se, dokud se k němu nepřihlásíš pomocí .subscribe()) a umožňuje data transformovat pomocí operátorů.

Služba (Service)

import { HttpClient } from '@angular/common/http';
import { Injectable, inject } from '@angular/core';
import { Observable, map } from 'rxjs';
@Injectable({ providedIn: 'root' })
export class UserService {
  private http = inject(HttpClient);
  // Vrací čistý proud dat (Observable)
  getUserObservable(): Observable<any> {
    return this.http.get('api/user').pipe(
      map(user => ({ ...user, localTime: new Date() })) // Transformace dat v proudu
    );
  }
}

Komponenta (Component)

import { Component, OnInit, OnDestroy, inject } from '@angular/core';
import { UserService } from './user.service';
import { Subscription } from 'rxjs';
@Component({ selector: 'app-user', template: `{{ user | json }}` })
export class UserComponent implements OnInit, OnDestroy {
  private userService = inject(UserService);
  private sub!: Subscription;
  user: any;
  ngOnInit() {
    // Přihlášení k odběru dat
    this.sub = this.userService.getUserObservable().subscribe({
      next: (data) => this.user = data,
      error: (err) => console.error(err)
    });
  }
  ngOnDestroy() {
    // Nutné ruční odhlášení, aby nevznikl memory leak
    this.sub.unsubscribe();
  }
}

Zde jsou všechny tři pokročilé ukázky. Ukazují, jak psát moderní Angular kód, který je čistý, efektivní a bezpečný proti únikům paměti (memory leaks).

1. Použití AsyncPipe v šabloně

Proč to chtít: Nemusíš v komponentě psát .subscribe() ani .unsubscribe(). Angular se o odběr dat a jeho zrušení při zániku komponenty postará sám.

Komponenta (TypeScript)

import { Component, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { CommonModule } from '@angular/common';
import { Observable } from 'rxjs';
@Component({
  selector: 'app-user-async',
  standalone: true,
  imports: [CommonModule], // Nutné pro async pipe
  template: `
    <!-- Použití async pipe přímo v HTML -->
    @if (user$ | async; as user) {
      <div>
        <p>Jméno: {{ user.name }}</p>
        <p>Email: {{ user.email }}</p>
      </div>
    } @else {
      <p>Načítám data...</p>
    }
  `
})
export class UserAsyncComponent {
  private http = inject(HttpClient);
  // Znak $ na konci je konvence pro proměnné typu Observable
  user$: Observable<any> = this.http.get('https://example.com');
}

2. Angular Signals (Nejnovější standard)

Proč to chtít: Od Angularu 16+ se jedná o nový způsob správy reaktivního stavu. Nepotřebuješ RxJS ani AsyncPipe. Kód je synchronní na pohled, ale reaktivní na pozadí.

Komponenta se signály

import { Component, inject, OnInit, signal, computed } from '@angular/core';
import { HttpClient } from '@angular/common/http';
@Component({
  selector: 'app-user-signals',
  standalone: true,
  template: `
    <div>
      <p>Uživatel: {{ fullName() }}</p>
      <button (click)="loadNextUser()">Další uživatel</button>
    </div>
  `
})
export class UserSignalsComponent implements OnInit {
  private http = inject(HttpClient);
  // Vytvoření zapisovatelného signálu s výchozí hodnotou
  user = signal<any>(null);
  userId = signal<number>(1);
  // Odvozený signál (vypočítá se automaticky při změně 'user')
  fullName = computed(() => {
    const u = this.user();
    return u ? `${u.firstName} ${u.lastName}` : 'Načítám...';
  });
  ngOnInit() {
    this.fetchUser(this.userId());
  }
  fetchUser(id: number) {
    this.http.get(`https://example.com{id}`).subscribe(data => {
      this.user.set(data); // Aktualizace signálu
    });
  }
  loadNextUser() {
    this.userId.update(id => id + 1); // Změna ID
    this.fetchUser(this.userId());     // Načtení nového uživatele
  }
}

3. Našeptávač (Autocomplete) pomocí RxJS

Proč to chtít: Ukazuje reálnou sílu RxJS operátorů. Tento kód počká, až uživatel přestane psát, ignoruje duplicitní dotazy a ruší předchozí (nedokončené) HTTP požadavky na server.

Komponenta s našeptávačem

import { Component, inject, OnInit } from '@angular/core';
import { FormControl, ReactiveFormsModule } from '@angular/forms';
import { HttpClient } from '@angular/common/http';
import { CommonModule } from '@angular/common';
import { Observable, debounceTime, distinctUntilChanged, switchMap, EMPTY } from 'rxjs';
@Component({
  selector: 'app-search',
  standalone: true,
  imports: [CommonModule, ReactiveFormsModule],
  template: `
    <input [formControl]="searchControl" placeholder="Hledej produkty...">
    <ul>
      @for (item of results$ | async; track item.id) {
        <li>{{ item.name }}</li>
      }
    </ul>
  `
})
export class SearchComponent implements OnInit {
  private http = inject(HttpClient);
  searchControl = new FormControl('');
  results$!: Observable<any[]>;
  ngOnInit() {
    this.results$ = this.searchControl.valueChanges.pipe(
      debounceTime(300),        // Počká 300ms od posledního stisknutí klávesy
      distinctUntilChanged(),   // Spustí se, jen pokud se text změnil oproti minule
      switchMap(searchTerm => { // Zruší předchozí HTTP požadavek, pokud ještě běžel
        if (!searchTerm || searchTerm.trim() === '') {
          return EMPTY;         // Pokud je pole prázdné, nic neposílá
        }
        return this.http.get<any[]>(`https://example.com{searchTerm}`);
      })
    );
  }
}

Pokud tě zaujal moderní přístup, můžeme se podívat na to, jak tyto koncepty propojit dohromady. V praxi se totiž často kombinuje RxJS (pro HTTP volání a našeptávače) s Angular Signals (pro uložení stavu v komponentě).

Chceš si ukázat, jak převést RxJS Observable na Signal pomocí funkce toSignal?

??? ukaž, jak převést RxJS Observable na Signal pomocí funkce toSignal

Funkce toSignal je vestavěný nástroj z balíčku @angular/core/rxjs-interop. Umožňuje vzít jakýkoliv stream z RxJS (Observable) a převést ho na Angular Signal.

Tím získáš výhody obou světů: silné operátory RxJS na zpracování dat a čistou, synchronně vypadající syntaxi Signálů v šabloně bez nutnosti používat AsyncPipe.

Kompletní ukázka: Převod Observable na Signal

Při převodu z Observable (která vrací data asynchronně až za nějaký čas) musíme vyřešit, jakou hodnotu má mít Signal předtím, než ze streamu dorazí první data. K tomu slouží parametr initialValue.

Služba (UserService)

import { HttpClient } from '@angular/common/http';
import { Injectable, inject } from '@angular/core';
import { Observable } from 'rxjs';
@Injectable({ providedIn: 'root' })
export class UserService {
  private http = inject(HttpClient);
  // Klasický RxJS stream, který chceme v komponentě převést
  getUsers(): Observable<any[]> {
    return this.http.get<any[]>('https://example.com');
  }
}

Komponenta (UserComponent)

import { Component, inject } from '@angular/core';
import { CommonModule } from '@angular/common';
import { UserService } from './user.service';
import { toSignal } from '@angular/core/rxjs-interop'; // Spojovací můstek mezi RxJS a Signals
@Component({
  selector: 'app-user-list',
  standalone: true,
  imports: [CommonModule],
  template: `
    <h2>Seznam uživatelů</h2>
    <!-- Používáme běžnou syntaxi signálu s kulatými závorkami () -->
    <ul>
      @for (user of users(); track user.id) {
        <li>{{ user.name }}</li>
      } @empty {
        <p>Žádní uživatelé nebo se data načítají...</p>
      }
    </ul>
  `
})
export class UserListComponent {
  private userService = inject(UserService);
  // Převod z Observable na Signal
  // initialValue definuje výchozí stav, než dorazí odpověď z API
  users = toSignal(this.userService.getUsers(), { initialValue: [] as any[] });
}

Důležitá pravidla pro práci s toSignal

  • Automatický unsubscibe: toSignal se automaticky odhlásí (unsubscribe) z odběru Observable ve chvíli, kdy komponenta zanikne. Nemusíš se bát memory leaků.
  • Kontext volání: toSignal musíte volat v tzv. injection kontextu – typicky přímo při definici vlastnosti třídy (jako v ukázce výše) nebo uvnitř konstruktoru. Nelze ho volat uvnitř běžných metod jako ngOnInit.
  • Vynechání initialValue: Pokud initialValue nezadáš, výchozí typ signálu bude obsahovat undefined (např. Signal<any[] | undefined>), dokud nedorazí první hodnota. Alternativně lze použít { requireSync: true }, pokud víš, že Observable vrátí hodnotu okamžitě (synchronně).

??? Chci se podívat, jak asynchronní data rovnou zobrazit v HTML šabloně pomocí vestavěného pipe async

Zobrazení asynchronních dat přímo v HTML šabloně pomocí async pipe je v Angularu nejlepší praxe.

async pipe se automaticky přihlásí (subscribe) k Observable nebo Promise, získá z nich data a při zničení komponenty se automaticky odhlásí (unsubscribe), čímž brání úniku paměti (memory leaks).

Zde je kompletní ukázka, jak na to.

1. Komponenta (TypeScript)

V komponentě nevoláte metodu .subscribe(). Pouze uložíte asynchronní proud dat (Observable) do proměnné. Podle konvence se tyto proměnné označují znakem $ na konci.

import { Component, OnInit } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs';
@Component({
  selector: 'app-uzivatele',
  templateUrl: './uzivatele.component.html'
})
export class UzivateleComponent implements OnInit {
  // Proměnná drží Observable, nikoliv samotná data
  uzivatele$!: Observable<any>;
  constructor(private http: HttpClient) {}
  ngOnInit() {
    // Pouze přiřadíme HTTP stream, nesubskribujeme ručně!
    this.uzivatele$ = this.http.get('https://typicode.com');
  }
}

2. Šablona (HTML)

V HTML použijete svislou čáru | a klíčové slovo async. Angular se postará o zbytek.

Možnost A: Výpis seznamu pomocí *ngFor

Ideální, pokud z API dostáváte pole objektů.

<ul>

  <!-- async pipe rozbalí Observable na reálné pole -->

  <li *ngFor="let uzivatel of uzivatele$ | async">

    {{ uzivatel.name }} ({{ uzivatel.email }})

  </li>

</ul>

Možnost B: Rozbalení objektu pomocí *ngIf a aliasu as

Pokud čekáte jeden objekt a chcete jeho vlastnosti vypsat na více místech, rozbalte ho jednou pomocí syntaxe as.

<!-- Kód uvnitř divu se zobrazí, až když data dorazí -->

<div *ngIf="uzivatele$ | async as seznamUzivatelu; else nacitani">

  <p>Celkový počet načtených uživatelů: {{ seznamUzivatelu.length }}</p>

</div>

<!-- Šablona pro stav, kdy se na data ještě čeká -->

<ng-template #nacitani>

  <p>Načítám data z databáze...</p>

</ng-template>

Hlavní výhody tohoto přístupu

  • Čistý kód: Žádný ruční .subscribe() v TypeScriptu.
  • Bezpečí: Angular vyřeší unsubscribe za vás, když uživatel odejde z této stránky.
  • Výkon: Skvěle spolupracuje se strategií detekce změn ChangeDetectionStrategy.OnPush, která zrychluje aplikaci.

Chcete vědět, jak pomocí RxJS operátorů tato asynchronní data v komponentě filtrovat nebo upravit ještě předtím, než dorazí do HTML? Nebo vás zajímá, jak u async pipe ošetřit případnou chybu sítě?

??? výrazy s "*" jako *ngIf, *ngFor jsou zastaralé, doporučuje se použít "@"-@if, @for

Máte naprostou pravdu. Od verze Angular 17 (vydané na konci roku 2023) představil Angular nový vestavěný blokový systém řízení toku (tzv. Control Flow). Ten nahrazuje staré direktivy s hvězdičkou (*ngIf, *ngFor, *ngSwitch) modernější syntaxí se zavináčem (@if, @for, @switch).

Tento nový přístup je rychlejší, nepotřebuje importovat CommonModule a má mnohem čistší zápis.

Zde je ukázka, jak vypadá stejný kód s async pipe v novém formátu @if a @for.

1. Nový @if s async pipe (Náhrada za *ngIf)

Už nepotřebujete vytvářet umělé elementy nebo značky ng-container, abyste uložili data do lokální proměnné.

@if (uzivatele$ | async; as seznamUzivatelu) {
  <p>Data úspěšně načtena!</p>
  <p>Počet uživatelů: {{ seznamUzivatelu.length }}</p>
} @else {
  <p>Načítám data z databáze...</p>
}

2. Nový @for s async pipe (Náhrada za *ngFor)

Nový @for vyžaduje parametr track. Ten nahrazuje dřívější (volitelnou) funkci trackBy a výrazně pomáhá Angularu s optimalizací překreslování stránky. Obsahuje také vestavěný blok @empty pro případ, že je pole prázdné.

<ul>
  @for (uzivatel of (uzivatele$ | async); track uzivatel.id) {
    <li>{{ uzivatel.name }} ({{ uzivatel.email }})</li>
  } @empty {
    <li>Nenalezeni žádní uživatelé.</li>
  }
</ul>

Poznámka: U @for se doporučuje dát výraz s async pipe do závorek (uzivatele$ | async), aby měl Angular absolutní jistotu, kde výraz začíná a končí).

Proč přejít na @ Control Flow?

  • Lepší výkon: Nový algoritmus pod kapotou je výrazně rychlejší při porovnávání změn v polích.
  • Žádné importy: Nemusíte do komponenty importovat NgIf nebo NgFor. Funguje to automaticky všude.
  • Méně kódu: Konstrukce @else a @empty šetří psaní dalších pomocných šablon (ng-template).
??? Chci vědět, jak pomocí RxJS upravit nebo filtrovat tato data

K úpravě nebo filtrování asynchronních dat předtím, než dorazí do HTML šablony, slouží v RxJS metoda pipe(). Uvnitř ní se používají takzvané operátory.

Pro úpravu struktury dat použijete operátor map, pro odfiltrování nechtěných položek operátor filter.

Zde je praktický příklad, jak data ze serveru upravit a vyfiltrovat.

1. Komponenta s RxJS operátory (TypeScript)

Představte si, že ze serveru přichází pole uživatelů. Chceme:

  1. Filtrovat: Ponechat pouze uživatele, kteří mají aktivní status.
  2. Upravit (Mapovat): Spojit jejich jméno a příjmení do jednoho pole celeJmeno, abychom to nemuseli spojovat v HTML.
import { Component, OnInit } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs';
// 1. Importujeme potřebné operátory
import { map } from 'rxjs/operators';
interface Uzivatel {
  id: number;
  jmeno: string;
  prijmeni: string;
  aktivni: boolean;
  celeJmeno?: string; // Tuto vlastnost sami doplníme
}
@Component({
  selector: 'app-filtrovani',
  templateUrl: './filtrovani.component.html',
  standalone: true
})
export class FiltrovaniComponent implements OnInit {
  uzivatele$!: Observable<Uzivatel[]>;
  constructor(private http: HttpClient) {}
  ngOnInit() {
    this.uzivatele$ = this.http.get<Uzivatel[]>('https://mojedomena.cz').pipe(
      // 2. Použijeme operátor map pro transformaci pole
      map((poleUzivatelu: Uzivatel[]) => {
        // Použijeme klasické JavaScriptové metody .filter() a .map() nad polem
        return poleUzivatelu
          // Ponecháme jen aktivní uživatele
          .filter(u => u.aktivni === true)
          // Každému uživateli přidáme novou vlastnost 'celeJmeno'
          .map(u => ({
            ...u,
            celeJmeno: `${u.jmeno} ${u.prijmeni}`
          }));
      })
    );
  }
}

Poznámka: Nezaměňujte RxJS operátor map (který zpracovává celý proud) s vestavěnou JavaScriptovou metodou pole .map() / .filter() uvnitř něj.

2. Čistá HTML šablona

V HTML se vůbec nic nemění. Použijete opět standardní async pipe. Výhodou je, že šablona dostane data už dokonale připravená k zobrazení.

<h3>Aktivní uživatelé</h3>
<ul>
  @for (uzivatel of uzivatele$ | async; track uzivatel.id) {
    <!-- Vypisujeme již upravené 'celeJmeno' -->
    <li>{{ uzivatel.celeJmeno }}</li>
  } @empty {
    <li>Žádní aktivní uživatelé nebyli nalezeni.</li>
  }
</ul>

Další užitečné RxJS operátory, které se vám mohou hodit:

  • tap: Slouží pro „vedlejší účinky“, které nemění data. Ideální pro console.log(data) uprostřed streamu, když potřebujete ladit kód.
  • take(1): Automaticky ukončí odběr po získání první hodnoty.
  • catchError: Zachytí chybu (např. výpadek serveru), abyste mohli vrátit náhradní prázdné pole a aplikace nespadla.
