1. Introduction to JavaFX 24

JavaFX is the modern Java UI toolkit for building desktop rich-client applications. It replaced Swing as Oracle's recommended GUI framework and ships separately as the open-source OpenJFX project (openjfx.io) since Java 11. JavaFX 24 is the current LTS-adjacent release and requires JDK 21+.

2. Application Architecture

JavaFX uses a scene graph — a tree of Node objects. All rendering, event dispatch, and property binding operate on this tree. The primary rule: all scene graph mutations must happen on the JavaFX Application Thread.

Stage / Scene / Node Hierarchy

  ┌─────────────────────────────────────────────────────┐
  │  Application  (lifecycle: init → start → stop)     │
  └──────────────────────────┬──────────────────────────┘
                             │  creates
                             ▼
  ┌─────────────────────────────────────────────────────┐
  │  Stage  (OS window)   stage.setScene(scene)         │
  └──────────────────────────┬──────────────────────────┘
                             │  contains
                             ▼
  ┌─────────────────────────────────────────────────────┐
  │  Scene  (root node + width/height + stylesheets)    │
  └──────────────────────────┬──────────────────────────┘
                             │  root
                             ▼
  ┌─────────────────────────────────────────────────────┐
  │  Node  (base)                                       │
  │  └── Parent  (has children)                        │
  │       └── Region  (has background, border, padding)│
  │            ├── Pane (HBox/VBox/GridPane/...)        │
  │            └── Control (Button/Label/TextField/...) │
  └─────────────────────────────────────────────────────┘

Threading Rules

// ❌  Background thread must NOT touch UI nodes
new Thread(() -> label.setText("bad")).start();
// ✅  Wrap UI update in Platform.runLater()
new Thread(() -> {
  String result = doHeavyWork();
  Platform.runLater(() -> label.setText(result));
}).start();
// Check which thread you're on:
boolean onFx = Platform.isFxApplicationThread();

5. FXML & Scene Builder

FXML is an XML-based declarative language for defining JavaFX UIs. It separates layout from logic — the controller class handles events while FXML defines structure. Scene Builder is a visual drag-and-drop tool that generates FXML.

FXML File (main.fxml)

<?xml version="1.0" encoding="UTF-8"?>
<?import javafx.scene.control.*?>
<?import javafx.scene.layout.*?>
<VBox xmlns:fx="http://javafx.com/fxml"
      fx:controller="com.example.MainController"
      spacing="10" padding="15">
  <Label text="Username:"/>
  <TextField fx:id="usernameField"
             promptText="Enter username"/>
  <Button text="Submit" onAction="#handleSubmit"/>
</VBox>

Controller Class

public class MainController {
  @FXML  // injected by FXMLLoader
  private TextField usernameField;
  @FXML
  private void initialize() {           // called after all @FXML fields are injected
    usernameField.setPromptText("Type here…");
  }
  @FXML
  private void handleSubmit(ActionEvent event) {
    String name = usernameField.getText();
    System.out.println("Hello " + name);
  }
}

Loading FXML in start()

@Override
public void start(Stage stage) throws IOException {
  FXMLLoader loader = new FXMLLoader(
      getClass().getResource("/com/example/main.fxml"));
  Parent root = loader.load();
  // Access controller after loading
  MainController ctrl = loader.getController();
  ctrl.initData(myModel);
  stage.setScene(new Scene(root, 800, 600));
  stage.show();
}

6. Properties & Bindings

JavaFX properties are observable wrappers around values. They power binding — linking a UI control's state directly to a model field so that changes propagate automatically without manual listeners in most cases.

Property Type Hierarchy

Observable

└── ObservableValue<T>

├── ReadOnlyProperty<T>

│ └── Property<T> (read + write)

│ ├── StringProperty → SimpleStringProperty

│ ├── IntegerProperty → SimpleIntegerProperty

│ ├── LongProperty → SimpleLongProperty

│ ├── DoubleProperty → SimpleDoubleProperty

│ ├── BooleanProperty → SimpleBooleanProperty

│ └── ObjectProperty<T>→ SimpleObjectProperty<T>

└── ObservableList<E>

├── FilteredList<E> (live-filtered view)

└── SortedList<E> (live-sorted view)

Model Class — Property Pattern

public class Person {
  private final StringProperty  name = new SimpleStringProperty();
  private final IntegerProperty age  = new SimpleIntegerProperty();
  // Standard accessor triple per property:
  public String         getName()         { return name.get(); }
  public void           setName(String v)  { name.set(v); }
  public StringProperty nameProperty()         { return name; }
  public int             getAge()         { return age.get(); }
  public void            setAge(int v)     { age.set(v); }
  public IntegerProperty ageProperty()         { return age; }
}

One-Way Binding (bind)

Label label = new Label();
// label.text always mirrors person.name
label.textProperty().bind(person.nameProperty());
// Composed expression: 'Alice is 30'
label.textProperty().bind(
  person.nameProperty().concat(" is ").concat(person.ageProperty().asString())
);
label.textProperty().unbind();  // must unbind before calling setText()

Bidirectional Binding

// Changes in tf propagate to model and vice-versa
tf.textProperty().bindBidirectional(person.nameProperty());
// Cross-type: IntegerProperty ↔ TextField text
tf.textProperty().bindBidirectional(
  person.ageProperty(), new NumberStringConverter());

ChangeListener & InvalidationListener

// ChangeListener<T>: receives old + new value
person.nameProperty().addListener((obs, oldVal, newVal) ->
  System.out.println(oldVal + " → " + newVal));
// InvalidationListener: fires when value *may* have changed
// cheaper — does not force evaluation of lazy bindings
person.ageProperty().addListener(obs ->
  System.out.println("Age invalidated"));

Bindings Utility — Conditional & Math Bindings

IntegerProperty a = new SimpleIntegerProperty(5), b = new SimpleIntegerProperty(3);
NumberBinding  sum  = a.add(b);             // a + b
NumberBinding  prod = Bindings.multiply(a, b);  // a * b
BooleanBinding gt   = a.greaterThan(b);       // a > b
// Ternary-style binding
label.textProperty().bind(
  Bindings.when(gt).then("A wins").otherwise("B wins")
);
// Disable a button when a field is blank
saveBtn.disableProperty().bind(
  nameField.textProperty().isEmpty().or(emailField.textProperty().isEmpty())
);

7. Event Handling

Events travel through the scene graph in three phases: capture (root→target), at-target, then bubble (target→root). Filters intercept events during capture; handlers process them during bubbling.

Event Dispatch Phases

  ┌──────────────────────────────────────────────────────┐
  │  1. CAPTURE (root ──► target)                        │
  │     addEventFilter() handlers called top-down        │
  ├──────────────────────────────────────────────────────┤
  │  2. AT-TARGET                                        │
  │     Both filters and handlers called on target node  │
  ├──────────────────────────────────────────────────────┤
  │  3. BUBBLE (target ──► root)                         │
  │     addEventHandler() handlers called bottom-up      │
  └──────────────────────────────────────────────────────┘
  event.consume() → stops further propagation anywhere
  setOnAction()   → shorthand for addEventHandler(ActionEvent)

8. CSS Styling

JavaFX uses a subset of CSS 2.1 with -fx- prefixed properties. Stylesheets attach to a Scene or any Node. CSS specificity mirrors web CSS: inline style > id selector > class selector > type selector.

Attaching Stylesheets

// Attach to whole scene (recommended)
scene.getStylesheets().add(
  getClass().getResource("/styles/app.css").toExternalForm()));
// Inline style (overrides stylesheet — avoid for maintainability)
btn.setStyle("-fx-background-color: #2196F3; -fx-text-fill: white;");
// CSS class — maps to  .my-button { }  in the stylesheet
btn.getStyleClass().add("my-button");
// CSS id — maps to  #submit-btn { }  in the stylesheet
btn.setId("submit-btn");

9. TableView & Observable Collections

TableView<T> is JavaFX's primary data grid. It binds directly to an ObservableList<T> — mutations to the list auto-refresh the table. PropertyValueFactory maps a column to the JavaFX property accessor on the model class.

Full TableView Setup

// ① Model with JavaFX properties
public class Product {
  private final StringProperty  name  = new SimpleStringProperty();
  private final DoubleProperty  price = new SimpleDoubleProperty();
  private final IntegerProperty qty   = new SimpleIntegerProperty();
  /* getters / setters / nameProperty() / priceProperty() … */
}
// ② Columns — type params: <ModelType, CellType>
TableColumn<Product,String>  nameCol  = new TableColumn<>("Name");
TableColumn<Product,Double>  priceCol = new TableColumn<>("Price");
TableColumn<Product,Integer> qtyCol   = new TableColumn<>("Qty");
// String arg must match the xProperty() method name prefix
nameCol.setCellValueFactory(new PropertyValueFactory<>("name"));
priceCol.setCellValueFactory(new PropertyValueFactory<>("price"));
qtyCol.setCellValueFactory(new PropertyValueFactory<>("qty"));
// ③ Data source
ObservableList<Product> data = FXCollections.observableArrayList();
data.addAll(new Product("Widget", 9.99, 50), /* … */);
// ④ Wire up
TableView<Product> table = new TableView<>();
table.getColumns().addAll(nameCol, priceCol, qtyCol);
table.setItems(data);

Custom Cell Factory

// Format price with color coding
priceCol.setCellFactory(col -> new TableCell<Product, Double>() {
  @Override
  protected void updateItem(Double price, boolean empty) {
    super.updateItem(price, empty);
    if (empty || price == null) { setText(null); setStyle(""); return; }
    setText(String.format("$%.2f", price));
    setStyle(price > 100 ? "-fx-text-fill: red;" : "");
  }
});

Filtering & Sorting with FilteredList / SortedList

ObservableList<Product> master = FXCollections.observableArrayList(/* … */);
FilteredList<Product> filtered = new FilteredList<>(master, p -> true);
searchField.textProperty().addListener((obs, old, txt) ->
  filtered.setPredicate(p -> {
    if (txt == null || txt.isBlank()) return true;
    return p.getName().toLowerCase().contains(txt.toLowerCase());
  })
);
SortedList<Product> sorted = new SortedList<>(filtered);
sorted.comparatorProperty().bind(table.comparatorProperty());
table.setItems(sorted);

10. Concurrency & Quick Reference

JavaFX provides Task<T> and Service<T> in javafx.concurrent for safe background work. Their progress, message, and value properties auto-post updates to the JavaFX Application Thread, so binding them to UI nodes is safe.

Task<T> — One-Shot Background Operation

Task<List<Product>> task = new Task<>() {
  @Override
  protected List<Product> call() throws Exception {
    updateMessage("Loading…");
    List<Product> list = db.fetchAll();
    updateProgress(1, 1);
    return list;
  }
};
// Bind UI to Task properties — safe across threads
progressBar.progressProperty().bind(task.progressProperty());
statusLabel.textProperty().bind(task.messageProperty());
task.setOnSucceeded(e -> {
  table.setItems(FXCollections.observableArrayList(task.getValue()));
  progressBar.progressProperty().unbind();
});
task.setOnFailed(e -> task.getException().printStackTrace());
new Thread(task).start();  // or executor.submit(task)

Service<T> — Restartable Background Service

public class SearchService extends Service<List<Product>> {
  private String query;
  public void setQuery(String q) { this.query = q; }
  @Override
  protected Task<List<Product>> createTask() {
    String q = query;  // capture — lambda runs on bg thread
    return new Task<>() {
      protected List<Product> call() {
        return db.search(q);
      }
    };
  }
}
SearchService svc = new SearchService();
svc.setOnSucceeded(e -> table.setItems(FXCollections.observableArrayList(svc.getValue())));
searchField.textProperty().addListener((obs, old, txt) -> {
  svc.setQuery(txt);
  svc.restart();  // cancels current task, starts new one
});

Common Pitfalls & Interview Points

Topic

Key Point

UI from wrong thread

Any scene graph write off the JavaFX Application Thread throws IllegalStateException at runtime. Wrap with Platform.runLater() or use Task properties.

Binding memory leak

A bound property holds a strong reference to the binding source. Always unbind() before discarding a node, or use WeakChangeListener.

ObservableList mutation

TableView / ListView only auto-refresh when items are mutated on the ObservableList (add/set/remove). Mutating a plain List inside it has no effect.

PropertyValueFactory matching

The String argument (e.g. "name") must match the xProperty() method name prefix exactly (case-sensitive). Mismatch → empty column, no exception.

@FXML field injection

The @FXML field name must match fx:id exactly. Mismatch leaves the field null; NullPointerException surfaces in initialize().

Task.call() thread

call() runs on a background thread. Never read or write scene graph nodes inside call(). Use updateMessage() / updateProgress() for safe UI feedback.

Module system (Java 9+)

Without module-info.java, add VM args: --add-opens javafx.graphics/... or open the controller package to javafx.fxml via module-info.

Stage ownership

Additional windows: new Stage(); newStage.initOwner(primaryStage) so they minimize/close together with the primary window.

TableView placeholder

An empty TableView shows 'No content in table'. Override with table.setPlaceholder(new Label("No results")).

FXML resources path

Use getClass().getResource("/absolute/path.fxml") (leading slash = classpath root). Relative paths break in JARs.
